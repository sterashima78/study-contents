# ADR 0008: 数学Cの3領域を追加し科目共通基盤を拡張する

- Status: Accepted
- Date: 2026-08-29
- Related: ADR 0002, ADR 0003, ADR 0005, ADR 0006, ADR 0007
- Extends: ADR 0007 の科目一覧と科目ホーム構成

## Context

数学I・数学Aでは、科目一覧 → 科目 → 領域 → 単元 → 小単元という情報階層、例題直後の誘導付き練習、小単元3問確認、単元末16問演習、公式・定理の導出分類を共通の学習体験としている。

数学Cを追加するにあたり、この構造を維持したまま、現行の高等学校学習指導要領に示される「ベクトル」「平面上の曲線と複素数平面」「数学的な表現の工夫」の3領域を学べるようにする必要がある。

「数学的な表現の工夫」では、日常や社会の事象を数学的に表現する題材として、図・表に加え、離散グラフや行列を用いる。行列については線形代数全体へ広げず、この領域で必要な基本的な読み取り、和、実数倍までを初期公開範囲とする。

このリポジトリは公開されているため、教材データに秘密情報や個人情報を含めず、回答や学習履歴を外部へ送信する仕組みも追加しない。

## Decision

### 1. 数学Cの3領域をすべて科目カタログへ登録する

`src/content/mathc/catalog.ts` を数学C教材の入口とし、次の3領域を登録する。

- `vectors`: ベクトル
- `curves-complex`: 平面上の曲線と複素数平面
- `mathematical-expression`: 数学的な表現の工夫

初期公開範囲は5単元・14小教材とする。

- ベクトル: 2単元・6小教材
- 平面上の曲線と複素数平面: 2単元・5小教材
- 数学的な表現の工夫: 1単元・3小教材

14小教材の規模では領域別ファイルへ細分化せず、1つのカタログで領域・単元・小単元の対応を見通せるようにする。教材量が増え、変更競合や可読性が問題になった時点で領域別ファイルへの分割を別ADRで判断する。

### 2. ADR 0007の科目階層へ数学Cを追加する

`src/content/math-courses.ts` の科目キーへ `mathc` を追加し、数学Cの科目ホームを `/mathc/` とする。

URLは次の構造とする。

```text
/mathc/
/mathc/{area}/
/mathc/{area}/{unit}/
/mathc/{area}/{unit}/{lesson}/
/mathc/{area}/{unit}/exercise/
```

トップページ `/` には数学I・数学Aと同列の科目カードとして数学Cを追加する。科目間の直接リンクは追加せず、別科目への移動はADR 0007どおり科目一覧を経由する。

### 3. 表示コンポーネントは既存の科目共通基盤を利用する

`MathAreaIndex`、`MathUnitIndex`、`MathLesson`、`MathUnitExercise` は既存の共通コンポーネントを利用する。

数学C固有の静的ルートは `src/pages/mathc/` に置き、`mathCCourse` と `mathCAreas` を共通コンポーネントへ渡す。

`MathLesson` は科目キーに応じて数学I・数学A・数学Cの公式導出レジストリを切り替える。これにより既存科目のURLと表示を変更せずに数学Cを追加する。

### 4. 演習は数学C専用レジストリを共通UIから利用する

`src/content/mathc/exercise-registry.ts` に数学Cの問題プールを置き、`ExerciseSet` が `courseKey=mathc` の場合に選択する。

各小単元は基礎・応用・難問の3問確認を持つ。単元末演習はADR 0002および数学Aと同じく、基礎12問・応用3問・難問1問の全16問とする。

採点、再出題、弱点診断はブラウザ内で完結させ、回答や学習状況は保存・送信しない。

### 5. 数式を掲載する小単元には導出または根拠を必須とする

ADR 0003の方針を数学Cにも適用し、`src/content/mathc/formula-derivations.ts` に公式・性質の根拠を登録する。

初期14小教材のうち数式を掲載する13小教材はすべて導出対象とし、数学Cについて新たな例外分類は設けない。

`scripts/verify-formula-coverage.mjs` は数学Cカタログと導出レジストリも走査する。数学Cはカタログ内で領域・単元・小単元を入れ子にしているため、検査は8文字以上のインデントを持つ `key` を追跡し、直前の小単元キーと `formulas` を対応付ける。

### 6. 代表ページの生成HTMLをCIで検証する

`scripts/verify-build-output.mjs` に次を追加する。

- トップページに数学Cが表示されること
- `/mathc/` に3領域・14小教材が表示されること
- ベクトルの内積で公式の根拠と3問確認が表示されること
- 複素数の極形式でド・モアブルの定理の根拠が表示されること
- 行列教材で行列の和と実数倍の根拠が表示されること
- ベクトル単元末演習が生成されること

これにより教材データ、静的ルート、導出表示、演習ページの接続不良をデプロイ前に検出する。

### 7. 依存関係は追加しない

数学Cの追加には既存のAstro、MathLive、Biomeだけを利用する。

2026-08-29時点でADR 0005に従い、Astro `7.2.9`、MathLive `0.110.0`、Biome `2.5.10`、pnpm 12系の最新公開版 `12.0.0-rc.9` を維持する。教材追加のためだけの新規依存関係は導入しない。

## Consequences

数学I・数学A・数学Cで、科目ページから小単元・確認問題・単元末演習まで同じ操作体系を維持できる。

数学C固有の教材データ、公式導出、演習生成ロジックは `src/content/mathc/` に閉じるため、他科目の教材内容と分離して変更できる。一方、表示基盤は共有するため、新しい科目キーを追加するときは `MathCourseInfo`、公式導出の選択、演習生成の選択、生成HTML検査を同時に更新する必要がある。

ADR 0007に記載された「初期状態では数学I・数学Aの2科目」という状態は、本ADRによって数学Cを含む3科目へ拡張される。ADR 0007の情報階層と科目間ナビゲーション方針自体は引き続き有効とする。
