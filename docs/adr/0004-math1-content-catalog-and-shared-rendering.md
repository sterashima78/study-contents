# ADR 0004: 数学Iの4領域を共通カタログと共通表示で管理する

- Status: Accepted
- Date: 2026-08-29
- Related: ADR 0001, ADR 0002, ADR 0003

## Context

これまでの実装は「数と式」だけを対象とし、教材データ、ページルーティング、表示コンポーネント、演習生成が `algebra` を前提としていた。

数学Iの未作成領域である「図形と計量」「二次関数」「データの分析」を追加すると、領域ごとに同種のページ実装を複製するか、数学I全体を共通の構造として扱う必要がある。

ADR 0001 の「領域 → 単元 → 小単元」、ADR 0002 の「小単元確認演習と単元末弱点診断」、ADR 0003 の「公式の導出または明示的な分類」は、新しい領域にも同じ基準で適用する必要がある。

また、既存の `/math1/algebra/...` URL は変更しない。

## Decision

### 1. 数学Iの領域を共通カタログで管理する

`src/content/math1/catalog.ts` を数学Iの領域一覧の入口とし、次の4領域を登録する。

- `algebra`: 数と式
- `geometry`: 図形と計量
- `quadratic`: 二次関数
- `data-analysis`: データの分析

各領域は複数の単元を持ち、各単元は ADR 0001 の粒度に従う小単元を持つ。

トップページの公開件数・単元リンクはこのカタログから生成し、手書きの「準備中」状態と実データが食い違わないようにする。

### 2. ページ表示とルーティングを領域非依存にする

新規ページは次の共通ルートで静的生成する。

```text
/math1/{area}/{unit}/
/math1/{area}/{unit}/{lesson}/
/math1/{area}/{unit}/exercise/
```

表示には `MathAreaIndex`、`MathUnitIndex`、`MathLesson`、`MathUnitExercise` を利用する。

`area=algebra` の場合も同じルートが従来の `/math1/algebra/...` を生成するため、既存URLを維持する。

### 3. 既存の数と式の演習生成は維持し、新領域用ジェネレーターを合成する

既存 `exercise-generators.ts` は数と式の問題生成ロジックとして維持する。

新3領域は `additional-exercise-generators.ts` に分離し、`exercise-registry.ts` で両者を共通インターフェースへまとめる。

これにより既存の出題ロジックを大きく書き換えず、全小単元に次を提供する。

- 小単元ごとの3問確認
- 単元末の基礎12問・応用3問・難問1問
- 問題と小単元の対応表示
- 採点後の弱点診断と復習リンク

問題生成・採点は引き続きブラウザ内だけで行い、回答を外部へ送信しない。

### 4. 公式導出を数学I全領域で検査する

既存の数と式の導出に加え、新領域の導出を `additional-formula-derivations.ts` に置き、`formula-registry.ts` から表示する。

`verify-formula-coverage.mjs` は4領域の教材ファイルと両方の導出ファイルを検査する。

公式を含む小単元は次のどちらかでなければならない。

- 既習事項からの導出・性質の根拠を掲載する
- 定義または出発点として明示的に例外分類する

相関係数の `−1 ≤ r ≤ 1` のように、完全な証明が数学Iの学習目標を大きく越える性質は、なぜこのページでは証明しないかを教材内で説明して利用する。

### 5. コンテンツの初期完成範囲

今回、数学Iの4領域を合計55小教材として公開可能な状態にする。

- 数と式: 18小教材（既存）
- 図形と計量: 12小教材
- 二次関数: 12小教材
- データの分析: 13小教材

各小教材は ADR 0001〜0003 の構成を満たすことを前提とする。

## Consequences

領域追加時には、教材データをカタログへ登録すれば共通ページ構造を利用できる。領域ごとの表示コンポーネント複製が不要になり、ナビゲーションや演習診断の挙動を揃えやすくなる。

一方、教材キーは演習・導出・診断リンクの対応に使われるため、キー変更は複数ファイルへ影響する。CIで公式分類と代表的な生成HTMLを確認し、カタログと生成物の不整合を検出する。
