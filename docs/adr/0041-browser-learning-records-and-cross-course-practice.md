# ADR 0041: 横断演習とブラウザ内学習記録

- Status: Accepted
- Date: 2026-08-30

## Context

ADR 0002 では、小単元確認演習と単元末演習をブラウザ内で生成・採点し、小単元別の弱点を確認する方針を決めた。一方、学習者が任意の領域を選んでまとまった問題数を解く入口と、複数回の演習結果を横断して強み・弱みを確認する仕組みはない。

学習履歴をサーバーへ保存すると、認証、個人データ管理、バックエンド運用が必要になる。このリポジトリは公開リポジトリであり、秘密情報や不要な個人データを持たない構成を維持したい。また、端末間で履歴を移動したい場合には、利用者自身が管理できるローカルファイルで十分な初期要件である。

## Decision

### 1. 全教材を横断する演習ページを設ける

`/practice/` に共通演習ページを置く。科目と領域を選択し、10・15・20・25・30問から問題数を指定できるようにする。

問題は各教材カタログの既存 `practice.steps` を共通問題バンクとして再利用する。問題文・正答・入力形式を別管理せず、教材本文と演習ページの不整合を避ける。選択領域の問題数が指定数に満たない場合は、重複出題を避けて利用可能な問題をすべて出題する。

### 2. 採点結果はブラウザの localStorage に保存する

学習記録は `study-contents:learning-records:v1` をキーとして localStorage に保存する。サーバー送信、外部分析サービスへの送信、アカウント同期は行わない。

保存するのは次の最小限の情報とする。

- 演習日時
- 科目・領域
- 指定問題数、実際の出題数、正解数
- 各設問が属する単元・小単元と正誤

入力した解答本文、正答文字列、自由記述内容は学習記録に保存しない。

### 3. 学習記録は最大500回に制限する

localStorage の容量を無制限に消費しないよう、保持する演習履歴は新しいものから最大500回とする。保存容量不足などで書き込みに失敗した場合は、採点結果を表示したうえで保存失敗を利用者へ通知する。

### 4. 学習記録ページで集計する

`/progress/` に学習記録ページを置き、総合正答率、回答問題数、演習回数、学習領域数、領域別成績、小単元別成績、直近の演習を表示する。

強み・復習候補は少数の偶然による誤判定を抑えるため、3問以上の履歴がある小単元だけを対象にする。初期基準は次の通りとする。

- 強み: 正答率80%以上
- 復習候補: 正答率60%未満

これは診断の確定判定ではなく、復習順序を決めるための補助情報として扱う。

### 5. JSONによるエクスポート・インポートを提供する

学習記録はバージョン付きJSON形式でローカルファイルへ書き出せるようにする。読み込み時は既存履歴へマージし、同一IDは重複させない。

インポートでは次を検証する。

- スキーマバージョン
- オブジェクト、文字列、数値、真偽値の型
- 1回あたり最大30問
- 最大500回の履歴
- 2MB以下の入力ファイル

未知フィールドを実行コードとして扱わず、検証済みフィールドだけを保存する。HTMLとして挿入せず `textContent` 等で表示する。

### 6. 新規依存関係を追加しない

ブラウザ標準API、既存の Astro、既存の MathLive を利用し、新しい保存・グラフ・状態管理ライブラリは導入しない。依存バージョン管理は ADR 0005 に従う。

## Consequences

学習者は教材を読み進める導線とは別に、任意の領域をまとめて演習し、複数回の結果から自分の傾向を確認できる。履歴は端末内だけに残るためプライバシーと構成の単純さを維持できる一方、ブラウザデータを削除すると履歴も失われる。必要な場合はJSONエクスポートでバックアップできる。

将来、アカウント同期やより高度な診断を導入する場合は、保存データの扱い、認証、プライバシー、スキーマ移行を別ADRで決定する。
