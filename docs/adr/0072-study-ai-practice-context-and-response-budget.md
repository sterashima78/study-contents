# ADR 0072: 練習問題のAI回答は具体的な1問を優先し短いプレーンテキストで返す

- Status: Accepted
- Date: 2026-08-31
- Related: ADR 0005, ADR 0049, ADR 0067

## Context

ADR 0067で `Llama-3.2-1B-Instruct-q4f16_1-MLC` へ切り替えた後、Android実機で自己診断と通常生成が正常化した。`1+1=` に対して `2` が返り、Qwen3各条件で発生した不規則な多言語・コード断片は再現しなかった。

このため、対象AndroidのWebGPU全般やWebLLM共通経路が壊れている可能性は大きく下がり、Qwen3のmodel artifact、モデル固有kernel、またはQwen3実行経路との組み合わせが主要因である可能性が高くなった。

一方、数学II「内分点・外分点の座標」で `練習問題の解き方を教えて。` と質問すると、Llama 3.2 1Bは同じ内容を「問題1」「問題2」などと複製して列挙し、最後は回答途中で終了した。

対象ページの実際のGuidedPracticeは1問であり、問題文は `A(−2,1), B(4,7) を 1:2 に内分する点を求める。` である。既存の教材コンテキスト抽出はviewport位置と質問語の一致度を優先して最大2セクションを選ぶため、`練習問題の解き方` のような一般的な質問では、1Bモデルにとって対象問題が曖昧になりやすかった。

また、UIはWebLLMの生成上限を320 tokensとしている。小型モデルが複数問題を列挙すると、この上限に達して回答が途中で終わる可能性がある。Androidでの安定性を優先し、現段階では生成上限を大きく増やすより、1回答の対象と長さを制約し、上限到達時は利用者へ明示する。

## Decision

### 1. 練習・演習質問ではGuidedPracticeを最優先コンテキストにする

質問に `練習`、`演習`、`問題`、`解き方`、`解法`、`ヒント` が含まれる場合、`[data-guided-practice]` の本文をviewportや一般的な関連セクション検索より先に教材コンテキストへ入れる。

GuidedPractice専用の抽出上限を760文字とし、問題文、各段階のprompt、ヒントを同じまとまりとしてモデルへ渡す。

回答入力欄、`math-field`、button等は従来どおり除外する。`data-answers` 属性はtextContentへ含まれないため、正答データをAIへ渡す設計にはしない。

### 2. 現在の質問をコンテキスト選択へ明示的に渡す

`StudyAIChat.astro` から `buildStudyContext(question)` を呼び、DOM上の最新質問を推測する経路だけに依存しない。練習問題優先判定と関連セクション検索が、送信された質問そのものを使うことを保証する。

### 3. 1回の回答では具体的な1問だけを説明する

system promptへ次を追加する。

- 練習問題・演習・解き方の質問では、`<study_context>` に明示された最も具体的な1問だけを対象にする。
- 複数問題を推測して作らない。同じ問題を番号だけ変えて列挙しない。
- 問題文の数値・条件を最初に確認し、使う考え方、計算手順、答えの順に説明する。
- 教材にない数値や条件を補わない。

### 4. 回答を原則250字程度に抑え、length終了を明示する

端末内1Bモデルでは、一度に広い範囲を説明させるより、短い回答を積み重ねる方を優先する。

回答は原則250字程度までとし、必要なら利用者に追加質問を促す。既存の320 token生成上限は維持し、Androidの推論時間とKV cache利用を抑える。

WebLLMのstreaming responseで `finish_reason === "length"` を検出した場合は、生成成功と同じ表示で無言に終了させない。回答末尾へ `回答が長いためここで区切りました。「続き」と入力してください。` を追加し、statusにも途中区切りであることを表示する。

### 5. Markdownを要求しない

回答UIは安全上 `textContent` を使う。`**見出し**` のようなMarkdownはレンダリングされず記号がそのまま表示されるため、system promptでMarkdown見出し・強調記号を使わずプレーンテキストで返すよう要求する。

HTMLとしての描画は導入しない。モデル出力をHTMLとして評価しない安全境界を維持する。

### 6. Llama 3.2 1Bを当面維持する

本変更ではモデルを変更しない。

`Llama-3.2-1B-Instruct-q4f16_1-MLC`、WebLLM 0.2.82、context window 2048、prefill chunk 128を維持し、まず教材参照と回答制御だけを改善する。

モデル品質比較は、このコンテキスト修正を実機で確認した後に別ADRで行う。

## Consequences

### Positive

- 「練習問題の解き方」のような一般的質問でも、実際の問題文と数値条件を優先してモデルへ渡せる。
- 1Bモデルが存在しない問題2・問題3を推測して列挙する可能性を下げられる。
- 既存の320 token上限を維持しながら、回答途中終了の可能性を下げられる。
- 上限へ達しても「続き」で再開できることを明示でき、途中終了を正常完了と誤認しにくい。
- Markdownを解釈するHTML描画を追加せず、既存のtextContent安全境界を維持できる。
- Llama実機成功と教材回答品質の問題を分離して評価できる。

### Negative

- 250字は複雑な問題の完全解説には短く、追加質問が必要になる場合がある。
- 320 token上限自体は維持するため、モデルが長さ指示を無視した場合は複数ターンになる。
- GuidedPractice以外の3問確認演習を明示的に指定された場合は、別の演習コンテキスト選択が必要になる可能性がある。
- WebLLM 0.2.82の一時固定は継続する。

## Validation

- `Llama-3.2-1B-Instruct-q4f16_1-MLC` を維持すること。
- WebLLM 0.2.82、context window 2048、prefill chunk 128を維持すること。
- `PRACTICE_CONTEXT_LIMIT = 760` を維持すること。
- 練習・演習質問では `[data-guided-practice]` が最優先コンテキストになること。
- `buildStudyContext(question)` で現在の質問を明示的に渡すこと。
- `finish_reason === "length"` の場合に途中区切りと「続き」の案内を表示すること。
- 入力欄やモデル出力をHTMLとして評価しないこと。
- system promptに1問限定、教材外条件の補完禁止、250字程度、プレーンテキストの制約があること。
- `pnpm check:study-ai` が通ること。
- `pnpm check` が通ること。
- `pnpm build` が通ること。
- Android実機で同じ教材ページから `練習問題の解き方を教えて。` を再実行し、実際の `A(−2,1), B(4,7), 1:2` を使った1問の説明になること。

## Supersedes

ADR 0067のモデルアーキテクチャ比較は、Llama 3.2 1BがAndroid実機で正常生成したことで診断目的を完了した。今後はLlama 3.2 1Bを基準に教材コンテキストと回答品質を改善する。
