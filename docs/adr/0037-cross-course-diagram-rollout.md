# ADR 0037: 説明図を科目別レジストリで段階的に展開する

- Status: Accepted
- Date: 2026-08-30
- Related: ADR 0019, ADR 0032, ADR 0034, ADR 0035, ADR 0036

## Context

ADR 0034 で `DiagramScene` と共通描画基盤を導入し、ADR 0036 では数学Iの `basic-parabola` を最初の実教材として `src/content/math1/diagrams.ts` の companion registry から配置した。

実教材を確認すると、数学Iの三角比、数学IIの単位円と三角関数、数学Cのベクトル、物理基礎の運動グラフと力の図示、数学IIIの接線と積分領域など、位置・向き・傾き・面積・構造を文章だけで説明している箇所が多数ある。これらは装飾ではなく、本文の意味を直接視覚化することで理解を補助できる。

一方、全科目の教材スキーマへ一度に図フィールドを追加すると影響範囲が大きい。科目ごとの図の成熟度も異なるため、既存の `lesson.key` を利用した companion registry を段階的に広げる方が安全である。

本ADRは ADR 0036 の「数学I以外の科目には影響させない」という暫定制限を置き換える。ADR 0036 の数学Iにおける配置スロット、色以外の識別手段、数学座標からの生成、練習問題への答え漏洩防止という決定は引き続き有効とする。

## Decision

### 1. 図示候補は学習上の必要性で選ぶ

次の情報を文章だけで説明している箇所を優先する。

- 位置関係、向き、角度、接続
- グラフの傾き、面積、周期、極値
- ベクトルや力の分解・合成
- 円、三角形、軌道などの幾何的関係
- 原子、細胞、回路などの構造

ページ装飾、単なる分類、本文と重複する学習フローを図にしない。ADR 0032 の方針を維持する。

### 2. 科目ごとに companion registry を持つ

各科目のコード生成説明図は `src/content/<course>/` 配下の図レジストリに置き、安定した `lesson.key` から解決する。小規模な科目では `diagrams.ts` にまとめ、既存レジストリが大きい場合や題材単位で分離した方が差分を小さく保てる場合は `trigonometry-diagrams.ts` のようなトピック別レジストリへ分割してよい。

同一科目内で複数レジストリを持つ場合は、科目外のレンダラーではなく科目横断 resolver の登録時に合成し、同じ `lesson.key` を複数レジストリへ重複登録しない。

配置スロットは ADR 0036 と同じく次を使う。

- `rule`: 概念説明後
- `example`: 例題の問題説明直後
- `exampleSteps`: 必要な例題手順

教材本文の配列順や表示タイトルをキーにしない。

### 3. MathLesson では科目共通の resolver を使う

`src/content/lesson-diagrams.ts` を科目横断の解決点とし、`MathLesson.astro` は特定科目を直接判定しない。

各科目を追加するときは resolver にその科目の registry を登録する。図を持たない科目は `undefined` を返し、既存表示へ影響させない。

### 4. 図は概念説明と例題を中心に配置する

練習問題では、図そのものが答えや途中結果を漏らす場合があるため、原則として説明図を追加しない。

作図回答として図が必要な場合は `DiagramExercise` を使い、説明用の図とは目的を分ける。

### 5. 展開順序を固定する

初期の優先順は次とする。

1. 数学I: 三角比
2. 数学II: 弧度法、単位円、三角関数のグラフ、三角方程式
3. 数学C: ベクトル
4. 物理基礎: 位置―時間グラフ、速度―時間グラフ、力の図示
5. 数学III: 接線、増減・凹凸、積分による面積・体積
6. 物理、化学、生物の構造・方向・接続を扱う単元

既に図示済みのレッスンは重複実装せず、未実装の次候補へ進む。

### 6. 数学的な図は計算値から生成する

関数グラフは ADR 0035 の `sampleFunctionPlot`、`createQuadraticPlot`、`CartesianTransform` などを利用し、表示用座標を本文へ手入力しない。

単位円上の点や特別角の三角形も、可能な範囲で角度・比などの数学的な値から座標を計算する。ラベルの可読性のための小さな表示オフセットは許容する。

### 7. 安全な既存描画基盤だけを使う

任意SVG、HTML、`innerHTML`、ブラウザで評価する式は導入しない。新しい外部描画ライブラリも追加しない。

図は既存の型付き `DiagramScene` と `DiagramElement` だけで表現し、既存の図データ検証を通す。

### 8. 入試・発展教材は引き続き対象外とする

`src/content/entrance/` については ADR 0019 の停止方針を維持する。通常教材で科目横断の作図運用と検証が安定してから、別ADRで再導入条件を判断する。

## Consequences

図示の効果が高い教材から小さく展開しながら、`MathLesson.astro` に科目別の条件分岐を増やさずに済む。図の生成ロジックは科目単位で追跡でき、既存教材スキーマも変更しない。

一方、図の利用状況は本文データだけでは把握できないため、教材編集時には各科目の図レジストリも確認する必要がある。科目数と図数がさらに増え、配置情報の横断検索が困難になった場合は、教材スキーマへの統合または自動インデックス生成を別ADRで検討する。
