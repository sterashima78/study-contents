# ADR 0006: 数学Aの3領域を追加し科目共通の表示基盤を利用する

- Status: Accepted
- Date: 2026-08-29
- Related: ADR 0001, ADR 0002, ADR 0003, ADR 0004, ADR 0005
- Superseded in part by: ADR 0007（科目ホームとトップページのナビゲーション）

## Context

数学IはADR 0001〜0004に基づき、領域 → 単元 → 小単元の階層、例題直後の誘導付き練習、小単元3問確認、単元末16問演習、公式・定理の導出分類を共通構造として実装している。

数学Aを追加するにあたり、この学習体験を複製実装するのではなく、数学Iで確立した構造を維持したまま科目だけを切り替えられるようにする必要がある。

現行の高等学校学習指導要領では、数学Aの内容として「図形の性質」「場合の数と確率」「数学と人間の活動」の3領域が示され、内容の取扱いでは整数の約数・倍数、ユークリッドの互除法、二進法、平面・空間の座標なども例示されている。

既存の数学I URLは変更しない。また、このリポジトリは公開されているため、教材の回答・学習履歴などを外部へ送信する仕組みは追加しない。

## Decision

### 1. 数学Aの3領域をすべて教材カタログへ登録する

`src/content/matha/catalog.ts` を数学Aの入口とし、次の3領域を登録する。

- `counting-probability`: 場合の数と確率
- `geometry-properties`: 図形の性質
- `human-activity`: 数学と人間の活動

初期公開範囲は23小教材とする。

- 場合の数と確率: 10小教材
- 図形の性質: 8小教材
- 数学と人間の活動: 5小教材

学習指導要領は数学Aの内容を適宜選択して履修させることとしているが、このサイトでは利用者が必要な範囲を選べるよう、3領域をすべて掲載する。

### 2. 表示コンポーネントを科目メタデータで切り替える

`src/content/math-courses.ts` に科目名、表示用キッカー、ルート、科目ホームへのパスを定義する。

既存の `MathAreaIndex`、`MathUnitIndex`、`MathLesson`、`MathUnitExercise` は科目情報を任意引数で受け取り、指定がなければ数学Iとして動作する。

これにより既存の数学Iページの呼び出し方とURLを維持しながら、数学Aでも同じ表示基盤を利用する。

数学AのURLは次とする。

```text
/matha/
/matha/{area}/
/matha/{area}/{unit}/
/matha/{area}/{unit}/{lesson}/
/matha/{area}/{unit}/exercise/
```

### 3. 演習は科目別レジストリを共通UIから呼び出す

`ExerciseSet` に `courseKey` を追加し、数学Iまたは数学Aの演習レジストリを選択する。

数学Aの各小単元には3問確認用の問題プールを用意する。単元末演習は既存方針と同じく、基礎12問・応用3問・難問1問の全16問とする。

採点、問題の再生成、弱点診断はブラウザ内で完結し、回答や学習状況をサーバーや外部サービスへ送信しない。

### 4. 公式・定理の導出分類を数学Aへ拡張する

ADR 0003の方針を数学Aにも適用する。

既習事項から短く説明できる公式・性質には `src/content/matha/formula-derivations.ts` で導出または根拠を掲載する。

確率・期待値・条件付き確率の定義や、その小単元で出発点として扱う基本定理は `scripts/verify-formula-coverage.mjs` で明示的に分類する。分類されていない数式表示が追加された場合はCIを失敗させる。

### 5. 数学と人間の活動は計算技能だけでなく活動との接続を扱う

「数学と人間の活動」では、学習指導要領の内容の取扱いを踏まえ、次を含める。

- 約数・倍数、最大公約数
- ユークリッドの互除法
- n進法・二進法
- 平面・空間の座標
- ゲームの勝敗状態と規則性

単なる公式一覧にせず、数の表現、効率的な手順、位置情報、ゲーム戦略など、人の活動の中で数学的な見方が働くことを教材の例題で示す。

### 6. 新しい依存関係は追加しない

数学Aの追加には既存のAstro、MathLive、Biomeだけを利用し、新規ライブラリは導入しない。

2026-08-29時点の公開レジストリ情報を確認し、ADR 0005で固定しているAstro `7.2.9`、MathLive `0.110.0`、Biome `2.5.10`、pnpm 12系の最新公開版 `12.0.0-rc.9` を維持する。Biome設定のスキーマも利用バージョン `2.5.10` に合わせる。

### 7. 生成HTMLの代表ページをCIで検証する

既存の数学Iの生成HTML検査に加え、数学Aの目次、確率、円、互除法、単元末演習の代表ページを `scripts/verify-build-output.mjs` で確認する。

教材データと静的ルート、公式根拠表示、演習ページのいずれかが欠けた場合にデプロイ前に検出する。

## Consequences

数学Iと数学Aで学習UIと演習体験を揃えながら、教材データと演習生成ロジックは科目別に分離できる。

既存の数学Iルートは維持される。今後別の数学科目を追加する場合も、科目メタデータとカタログを追加する形へ拡張しやすくなる。

一方、演習の診断リンクは `courseKey`、`areaKey`、`unitKey`、`lessonKey` の整合性に依存するため、教材キーを変更するときはカタログ・演習レジストリ・生成HTML検査を同時に更新する必要がある。
