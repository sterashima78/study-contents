# ADR 0042: ブラウザ内AIを教材共通の学習チューターとして提供する

- Status: Superseded
- Date: 2026-08-30
- Superseded by: ADR 0046
- Related: ADR 0005, ADR 0022, ADR 0040, ADR 0041

## Context

各章・単元・小単元の教材を閲覧中に、分からない考え方や問題について、そのページの内容を前提として質問できる支援機能が必要になった。

外部AI APIを直接利用すると、公開リポジトリにAPIキーを置かないためのサーバー境界、利用量制御、利用者データの送信方針が別途必要になる。一方、このサイトは静的教材として配信しているため、WebGPU対応ブラウザでモデルを端末内実行できれば、既存の静的配信を維持したままAI支援を追加できる。

教材には問題の正答や生成ロジックがブラウザ側スクリプトとして含まれる場合がある。AIがページ全体のHTMLやスクリプトを無差別に参照すると、ヒントを求めただけでも内部正答を利用してしまう。また、生成したAIテキストをHTMLとして描画すると、モデル出力を信頼境界の内側へ入れることになる。

ADR 0005 により、新規ライブラリは確認時点の最新公開版を完全なバージョンで固定する。2026-08-30 の確認時点では `@mlc-ai/web-llm@0.2.84` を採用可能であり、Web Worker経由の推論とQwen3系の事前構築モデルを利用できる。

## Decision

### 1. WebLLMによるブラウザ内推論を採用する

`@mlc-ai/web-llm@0.2.84` を直接依存へ追加し、外部AI APIやAPIキーを使用しない。

初期モデルは WebLLM の事前構築モデル `Qwen3-1.7B-q4f16_1-MLC` に固定する。モデルIDやモデルURLを利用者入力から受け取らず、アプリケーション側の定数だけから選択する。

このモデルはWebLLMの現行設定でコンテキスト長4096、必要VRAMの目安が約2GBであるため、初期版ではこれを対応端末の基準とする。

### 2. モデルは質問送信時に遅延ロードし、専用Web Workerで実行する

教材ページを開いただけではWebLLM本体やモデルを初期化しない。最初の質問送信時に動的importとWeb Worker生成を行い、そのとき初めてモデルをロードする。

推論は `WebWorkerMLCEngineHandler` と `CreateWebWorkerMLCEngine` を使い、教材本文のスクロールや入力UIをモデル推論でブロックしない。

初期版ではService Workerによるページ遷移をまたいだエンジン常駐を採用しない。ブラウザキャッシュによるモデル成果物の再利用は利用するが、推論エンジンの長寿命化はライフサイクルと障害復旧を別途検証してから判断する。

### 3. AIチャットは共通StudyPageに配置する

`src/components/ui/StudyPage.astro` から `StudyAIChat.astro` を1回だけ描画し、StudyPageを利用する教材ページから常に呼び出せるようにする。

デスクトップでは右下の固定ボタンからパネルを開き、モバイルでは画面下部から大きなパネルとして表示する。チャットを開いていない状態では本文の閲覧を妨げない。

### 4. 教材コンテキストは表示済み本文から安全に抽出する

AIへ渡す教材情報は `main.study-page` の表示テキストを基準とし、ページタイトル、説明、パス、現在のビューポート付近の節、ページ本文を組み立てる。

ただし、次の要素はコンテキストから必ず除外する。

- `script`
- `style`
- `template`
- AIチャット自身の `data-study-ai-exclude`
- `input`、`textarea`、`select`、`button`
- `math-field`

これにより、教材として実際に表示されている問題文や説明は参照できる一方、演習生成コードや正答配列など、画面本文ではない内部データをAIへ渡さない。

コンテキスト長を制御するため、ビューポート付近の内容とページ全文はそれぞれ上限文字数で切り詰める。会話履歴もモデル入力時には直近3件、各600文字までに制限し、4096トークンのコンテキスト内に回答余地を確保する。

### 5. システムプロンプトは学習支援を優先する

AIは現在の教材を最優先の参考資料とし、原則として日本語で段階的に説明する。

問題については、求めるもの、使う考え方、次の一手の順に支援し、利用者が明確に完全解答を求めた場合だけ途中過程と最終結果まで説明する。

`<study_context>` 内の文章は信頼できるシステム命令ではなく教材データとして扱うよう明示し、教材本文に命令文が含まれてもプロンプト制御へ利用しない。

Qwen3の思考モードは初期版では `enable_thinking: false` とし、応答時間と生成量を抑えて対話的な学習支援を優先する。

### 6. AI出力をHTMLとして評価しない

モデル出力はDOMの `textContent` だけで描画する。`innerHTML`、任意HTML、モデル生成MarkdownをHTMLへ変換する処理は導入しない。

数式の高度な組版は初期版の対象外とし、まず安全なプレーンテキスト表示を優先する。将来AI出力をMathLive等で表示する場合は、ADR 0040の教材管理下データとは信頼境界が異なるため、利用者入力・モデル出力向けのサニタイズ方針を別途決定する。

### 7. 会話履歴はページ単位のsessionStorageに限定する

会話履歴は現在のパスをキーとして `sessionStorage` に最大10件だけ保持する。ADR 0041の演習結果用 `localStorage` とは用途と保存期間を分け、AI会話を学習記録へ混在させない。サーバーへの保存、分析基盤への送信、永続的なユーザープロファイル化は行わない。

利用者はチャットパネルから履歴を消去できる。ストレージが利用できないプライバシーモードでも、永続化なしでチャット自体は動作できるようにする。

### 8. WebGPU非対応と既知のWebLLM障害を明示的に処理する

WebGPUまたはWorkerが利用できないブラウザでは、AI入力を無効化して非対応であることを表示する。

WebLLM 0.2.84 には、一部の低性能AMD統合GPUで長いプロンプトを処理した際に `device hung` や `Object has already been disposed` が発生する未解決報告がある。ADR 0005の最新版利用方針を維持して0.2.84を採用するが、端末依存障害としてエラーメッセージを表示し、WebLLMの次期リリースで修正状況を再評価する。

構造化レスポンス機能は初期版で使用せず、通常のストリーミングテキスト生成だけを利用する。

## Consequences

### Positive

- APIキーやサーバー側AIプロキシを追加せず、静的サイトの構成を維持できる。
- 質問内容、教材コンテキスト、会話履歴を外部AI APIへ送信しない。
- すべてのStudyPage利用ページから共通UIでAIチューターを呼び出せる。
- モデルロードを利用開始時まで遅延でき、AIを使わない閲覧者へ大きな初期負荷を与えない。
- 内部正答データとモデル生成HTMLを信頼境界から除外できる。

### Negative

- WebGPU非対応端末では利用できない。
- 初回利用時には約2GB級のモデル実行資源に加え、モデル成果物のダウンロードとキャッシュが必要になる。
- 端末性能によって生成速度と安定性が大きく異なる。
- フルページ遷移では推論エンジンを作り直すため、キャッシュ済みでも初期化時間が発生する。
- 小型ローカルモデルであるため、クラウド上の大型モデルより回答品質が低い場合がある。

## Validation

- `pnpm install` で `@mlc-ai/web-llm@0.2.84` とlockfileが一致することを確認する。
- `pnpm check` を実行し、ADR採番、既存教材、図、スタイル境界、AIセキュリティ境界を含む検証を通す。
- `pnpm build` を実行し、Web Workerと遅延ロード用チャンクを含めて静的ビルドできることを確認する。
- WebGPU対応ブラウザで初回ロード進捗、ストリーミング回答、停止、履歴消去を確認する。
- WebGPU非対応環境で教材本文は通常どおり閲覧でき、AI入力だけが無効になることを確認する。
- 生成回答が `textContent` で描画され、モデル出力がHTMLとして実行されないことを確認する。
- 演習ページで `script` 内の正答配列がAIコンテキストへ含まれないことを確認する。
