# ADR 0036: 数学Iのコード生成説明図をレッスン配置レジストリで管理する

- Status: Accepted
- Date: 2026-08-30
- Related: ADR 0019, ADR 0034, ADR 0035

## Context

ADR 0034 で共通の `DiagramScene` と描画コンポーネントを導入し、ADR 0035 で任意色指定と数学座標計算ヘルパーを追加した。

数学Iで最初に適用する `y = ax²` の説明図は、固定の座標列ではなく係数から `createQuadraticPlot` を使って生成する。こうした図は教材本文そのものというより、教材のパラメータから生成される表示用データであり、長い `samples` や座標計算を本文データへ直接埋め込むと可読性を下げる。

また、数学教材共通の `MathLesson.astro` は数学I以外の科目でも利用されているため、数学Iの試行導入だけを理由に全科目の教材スキーマへ図フィールドを追加するのは影響範囲が大きい。

## Decision

### 1. 数学Iのコード生成図は companion registry で管理する

`src/content/math1/diagrams.ts` に、`lesson.key` から説明図を解決するレジストリを置く。

初期の配置スロットは次とする。

- `rule`: RULE セクションの概念説明後に表示する図
- `example`: EXAMPLE の問題説明直後に表示する図
- `exampleSteps`: 必要な場合だけ例題の特定手順に表示する図

教材本文の配列順や概念タイトルを配置キーとして利用せず、安定した `lesson.key` を使う。

### 2. 数学I以外の科目には影響させない

`MathLesson.astro` は `course.key === "math1"` の場合だけ数学Iの図レジストリを参照する。

他科目へ展開する場合は、各科目で同様の companion registry を持つか、複数科目で共通化する必要が生じた時点で別ADRにより共通インターフェースを決定する。

### 3. 最初の対象は `basic-parabola` とする

`y = ax²` のページで次の2図を表示する。

RULE では、`y=x²`、`y=2x²`、`y=0.5x²`、`y=−x²` を同一座標上に描き、係数の符号と絶対値による形の違いを比較する。

EXAMPLE では `y=2x²` を描き、頂点 `(0,0)` と対称な2点 `(−1,2)`、`(1,2)` を示す。

### 4. 色だけを意味の識別手段にしない

複数曲線を色分けするが、各曲線には `y=...` の式ラベルも直接付ける。

色覚差、モノクロ表示、低コントラスト環境でも曲線を識別できるようにし、色は補助的な手掛かりとして扱う。

### 5. 座標は数学座標から計算する

曲線は ADR 0035 の `createQuadraticPlot` で生成し、目盛・点・式ラベルも `CartesianTransform` を経由して配置する。

教材作成者がグラフの形をSVG座標で直接調整することを基本方針とせず、数学的な値と表示位置の対応を保つ。

ラベルの可読性確保に必要な数ピクセルのオフセットだけは表示調整として許容する。

### 6. 練習問題には当面図を追加しない

`basic-parabola` の練習では、係数から開く向きや値を自力で判断させるため、答えを直接示す図は表示しない。

説明図と解答入力を分離し、図による答えの漏洩を避ける。

### 7. 入試・発展教材の停止方針は変更しない

本ADRは通常の数学I教材への説明図導入であり、ADR 0019 の `src/content/entrance/` に対する図解停止を解除しない。

## Consequences

数学Iの本文データを大きく変更せず、計算ヘルパーを使った図を実教材へ導入できる。説明図の生成ロジックが1か所にまとまり、係数・数学座標・描画座標の不整合を抑えられる。

一方、図の配置は本文データから直接は見えないため、教材編集時には `src/content/math1/diagrams.ts` も確認する必要がある。図の利用が多数の科目・多数のページへ広がった場合は、配置情報を教材スキーマへ統合するか、共通レジストリを設計し直す。
