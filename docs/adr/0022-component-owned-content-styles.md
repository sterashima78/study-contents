# ADR 0022: 教材表現をAstroコンポーネント化しスタイル所有範囲を限定する

- Status: Accepted
- Date: 2026-08-29
- Related: ADR 0001, ADR 0004, ADR 0006, ADR 0007, ADR 0010, ADR 0013, ADR 0016, ADR 0019, ADR 0021
- Updates: 教材UIのスタイル管理を共有クラス中心からコンポーネント所有へ移行する

## Context

公開教材が増え、通常教材、単元一覧、演習、応用・発展教材がそれぞれ `global.css`、`lesson.css`、`exercise.css`、`entrance.css` などの共有クラスを参照していた。

この構成では `.section-label`、`.primary-button`、`.skill-list`、`.pattern-header` など意味の異なる画面が同じクラス名や詳細度の異なるセレクタを共有し、追加順やCSSの読み込み順によって表示が変化し得る。実際に応用・発展教材を全科目へ広げた後、スタイル崩れが確認された。

また、教材の表現単位がHTML断片とCSSクラスの組み合わせに分散していると、同じ「例題」「誘導練習」「一覧」「ナビゲーション」を別ページで再実装しやすく、表示・アクセシビリティ・レスポンシブ対応の整合性を保ちにくい。

## Decision

### 1. 教材内で繰り返す視覚表現はAstroコンポーネントとして実装する

現在の公開教材で共通に使う次の表現を `src/components/ui/` のAstroコンポーネントとして管理する。

- ページシェル
- パンくず
- ヒーロー
- セクション見出し
- 学習フロー
- 概要メトリクス
- タグ・技能一覧
- カード/行形式の一覧
- 概念・公式カード
- 例題と途中過程
- ステップバイステップ練習
- 実践問題と解答表示
- 要点一覧
- CTAパネル
- 前後ナビゲーション
- フッター

トップページ、科目目次、領域、単元、小単元、単元末演習、応用・発展をこれらの部品で構成する。

### 2. 各コンポーネントが自分のスタイルを所有する

静的に生成される教材UIはAstroの `<style>` をコンポーネント内に置き、Astroのscoped styleを利用する。

親ページから子コンポーネント内部のDOM構造やクラス名を前提にしたスタイル指定は行わない。コンポーネント間で共有するのはCSSカスタムプロパティによる色・境界・フォーカス色などのデザイントークンまでとする。

### 3. `global.css` はリセットとデザイントークンだけに限定する

`src/styles/global.css` は次だけを保持する。

- フォント・基本色・背景
- CSSカスタムプロパティ
- `box-sizing`
- `body` の基本余白と背景
- フォーム要素のフォント継承

教材固有のクラスセレクタを `global.css` に置かない。

`global.css` のimportはページ境界を作る `StudyPage.astro` のみに集約する。

### 4. ブラウザで動的生成する演習DOMはルート要素へCSSスコープを固定する

`ExerciseSet.astro` と `PhysicsExerciseSet.astro` は問題カードをクライアント側JavaScriptで生成するため、生成後のDOMへAstroのscoped属性を自動付与できない。

この2コンポーネントに限り `exercise.css` を共有し、CSS `@scope` のスコープルートを次に固定する。

- `[data-exercise-set]`
- `[data-physics-exercise-set]`

これにより `.primary-button` などの一般的なクラス名も演習ルートの外には作用しない。

### 5. 旧ページ横断CSSを廃止する

次の共有CSSは削除し、新規importを禁止する。

- `lesson.css`
- `entrance.css`
- `entrance-index.css`
- `lesson-interactive.css`

通常教材と応用・発展教材が別々の共有CSSを持つ構成へ戻さない。

### 6. CIでスタイル境界を検証する

`scripts/verify-component-styles.mjs` を追加し、次を検証する。

- `global.css` にクラスセレクタがないこと
- `global.css` のimportが `StudyPage.astro` だけであること
- 廃止した共有CSSをimportしていないこと
- `exercise.css` が2つの演習コンポーネント以外からimportされていないこと
- `exercise.css` が指定した `@scope` を持つこと
- 主要な教材UIコンポーネントが `<style>` を所有していること
- 旧レイアウト用クラス名をAstroファイルで使用していないこと

PR CIとPagesデプロイ前チェックの両方で実行する。

### 7. コンテンツデータ・URL・採点方式は変更しない

本変更は表示責務とスタイル境界の整理であり、教材内容、既存URL、演習問題生成、ブラウザ内採点、権利メタデータの方針は変更しない。

新しい依存ライブラリも追加しない。

## Consequences

教材の追加時に既存ページのクラス詳細度やCSS読み込み順を意識する必要が減り、表示崩れをコンポーネント単位へ局所化できる。

通常教材と応用・発展教材で同じ表現部品を共有するため、同一の「例題」「練習」「一覧」について見た目やアクセシビリティの差分が生じにくくなる。

一方、動的演習UIはAstro scoped styleだけでは完結できないため、ルートを明示したCSS `@scope` を例外として維持する。この例外はCIで対象コンポーネントを固定し、他の教材UIへ拡大しない。
