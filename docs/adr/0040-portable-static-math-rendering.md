# ADR 0040: 数式表示にMathLive静的レンダリングと可搬テキストを使い分ける

- Status: Accepted
- Date: 2026-08-30

## Context

数学Cのベクトル教材では、添字を `₁` / `₂`、ベクトル記号を結合文字 `⃗` で表した既存データがある。これらを通常のHTMLテキストやSVGの `<text>` として表示すると、端末とフォントの組み合わせによってグリフが存在せず、iOSを含む一部環境で欠字の四角形として表示される。

既存の入力UIでは MathLive を利用しており、依存関係は `mathlive@0.110.0` に固定されている。数式表示のためだけに別の数式ライブラリや外部CDNを追加すると、依存関係、配信経路、セキュリティ確認の範囲が増える。

また、教材には「数式だけの表示」と「日本語文中に数式記号が混在する表示」があり、すべてを同じレンダリング方式へ一括変換すると、既存教材のレイアウトや読み上げ、SVG作図に不要な影響を与える可能性がある。

## Decision

### 1. 数式だけの表示はMathLiveの静的レンダリングを利用する

端末依存の欠字が発生し得る数式文字を含む式について、MathLiveのサーバーサイド静的レンダリングを利用する。

共有コンポーネント `StaticMath.astro` で `mathlive/ssr` の `convertLatexToMarkup()` を呼び出し、`mathlive/static.css` と組み合わせて表示する。クライアント側のMathfieldを生成せず、表示専用の式ではハイドレーションを要求しない。

既存データは直ちに全件LaTeXへ書き換えず、`src/lib/math-display.ts` にUnicode疑似数式からLaTeXへの互換変換を集約する。これにより、ベクトル記号、添字、上付き数字、平方根などをMathLiveが扱える表現へ変換する。

### 2. 日本語との混在テキストとSVGラベルは可搬テキストへ正規化する

日本語文中のベクトル記号やSVGのラベルは、MathLiveのHTMLマークアップを直接埋め込めない、または埋め込む費用が大きい。そのため共有関数 `toPortableMathText()` を通し、フォント依存性の高い表現を基本的な文字へ置き換える。

初期ルールは次の通りとする。

- Unicode下付き数字 `₀` から `₉` は通常数字へ変換する
- 結合文字による `AB⃗` のような表記は `AB→` のような可搬表記へ変換する

この正規化は表示時だけに行い、教材データそのものや正答判定用データは変更しない。

### 3. 既存の安定している数式表示は段階的に移行する

今回の障害に関係しない既存数式まで一括してMathLiveへ変更しない。欠字リスクのある文字を検出した場合に静的数式レンダリングを使用し、それ以外は既存のプレーンテキスト表示を維持する。

将来、新規に複雑な数式を追加する場合は、Unicodeの見た目だけで数式を組み立てる方法よりLaTeXと静的数式レンダリングを優先する。

### 4. 外部CDNや新規依存関係は追加しない

既に導入済みのMathLiveを利用し、外部CDNからスクリプト、スタイル、フォントを読み込まない。リポジトリ管理下の依存関係とビルド成果物だけで表示を完結させる。

静的数式へ渡す値は現時点ではリポジトリ内で管理する教材データに限定する。将来、利用者入力や外部データを静的数式として表示する場合は、入力境界とサニタイズ方針を別途設計する。

### 5. 共有表示層で対策する

個々の数学C教材だけを書き換えるのではなく、次の共有表示層で対策する。

- `ConceptCard.astro`: 欠字リスクを含む数式を静的数式として描画する
- `WorkedExample.astro`: 数式だけの手順を静的数式として描画し、混在文は可搬テキスト化する
- `MathLesson.astro`: 練習問題やまとめなどの混在文を可搬テキスト化する
- `DiagramCanvas.astro`: SVGラベルを可搬テキスト化する

これにより、数学C以外で同じ文字表現が追加された場合にも共有層で同じ対策を適用できる。

## Consequences

### Positive

- iOSなど特定フォントで添字や結合ベクトル記号が欠字になる問題を避けられる。
- 数式だけの表示ではベクトル、添字、平方根などを数式組版として表示できる。
- 新しい数式ライブラリや外部CDNを追加せず、既存のMathLiveを再利用できる。
- Unicode疑似数式の互換処理が一箇所に集約され、表示コンポーネントごとの個別置換を避けられる。
- SVGを含む、MathLiveを直接使いにくい表示にも同じ可搬性方針を適用できる。

### Negative

- 混在文とSVGでは `AB⃗` を `AB→` と表示するため、教科書的な上付き矢印と見た目が完全には一致しない。
- 既存Unicode表現をLaTeXへ変換する互換層が必要になる。
- すべての数式を同時に統一するのではなく段階移行となるため、当面はプレーンテキスト数式と静的数式が併存する。

## Validation

- `pnpm check` でADR、コンテンツ、作図、コンポーネントスタイルを含む既存検証を通す。
- `pnpm build` でMathLiveのSSRエントリポイントと静的CSSがAstroのビルドに含まれることを確認する。
- 数学C「ベクトルと成分表示」のルール、例題、練習、作図で `₁` / `₂` / `⃗` が欠字として表示されないことをモバイル幅で確認する。
