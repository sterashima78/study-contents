# ADR 0033: 問題ごとに回答入力方式を設計する

- Status: Accepted
- Date: 2026-08-30

## Context

例題直後の GuidedPractice は、従来すべての回答を通常のテキスト入力として扱っていた。一方で、学習上必要な操作は問題ごとに異なる。式を組み立てる問題では数式入力が必要であり、候補から1つを判断する問題ではラジオボタンまたはセレクト、複数候補を選ぶ問題ではチェックボックス、語句や文章を書く問題では通常のテキスト入力が適する。

入力UIを科目単位で固定すると、問題が測定したい能力と回答操作がずれる。特に数学で全回答を数式入力にすることや、選択問題をすべてセレクトにすることは避ける必要がある。

## Decision

GuidedPractice の各ステップが回答方式を明示できるようにする。

回答方式は次を基本とする。

- `math`: 数式を構成・変形・計算して回答する。MathLive の MathfieldElement を使う。
- `text`: 単語、短文、説明などを自由入力する。ネイティブのテキスト入力を使う。
- `radio`: 少数の選択肢を比較して1つ選ぶ。選択肢を常時表示する。
- `select`: 選択肢が多い、または表示密度を下げたい1択問題に使う。ネイティブ select を使う。
- `checkbox`: 複数の正解候補を選択する問題に使う。

入力方式は科目名や選択肢数のみから自動推測せず、コンテンツ設計時に問題ごとに決める。ラジオとチェックボックスは fieldset/legend を使い、select には未選択状態を用意する。

既存コンテンツとの互換性のため、回答方式未指定のステップは当面 `text` として扱う。ただし、新規・改修する問題では回答方式を明示する。

数学の式回答では ExerciseSet と同じ MathLive を再利用し、LaTeX 表現差を吸収する正規化を行う。スマートフォンでは MathLive の仮想数式キーボードを利用でき、PCでは物理キーボード入力を維持する。

## Consequences

- 問題が測る能力と入力操作を一致させやすくなる。
- 数式入力が必要な問題だけで数式キーボードが開くため、モバイルの占有面積を抑えられる。
- 選択問題は選択肢の性質に応じて radio/select/checkbox を使い分けられる。
- GuidedPractice の採点処理は複数の入力要素を扱う必要がある。
- 既存問題は段階的に回答方式を明示していく必要がある。

## Implementation notes

- `GuidedPractice.astro` は回答方式に応じて適切なコントロールを描画する。
- 数式回答は MathLive の値を採点時に正規化する。
- 選択肢の正解値は表示ラベルから分離できるようにする。
- 数学の展開練習など、式を自分で構成すること自体が学習目標の問題は `math` を選ぶ。
- 「どの公式を使うか」など判断を測る問題では `radio` または `select` を選び、不要な文字入力を求めない。
