# ADR 0021: 公開済み全科目の領域へ応用・発展パターンを展開する

- Status: Accepted
- Date: 2026-08-29
- Related: ADR 0001, ADR 0002, ADR 0007, ADR 0013, ADR 0014, ADR 0015, ADR 0016, ADR 0017, ADR 0018, ADR 0019, ADR 0020
- Updates: ADR 0020 の数学I向け応用・発展表示を科目共通へ一般化し、公開済み全科目へカバレッジを拡張する

## Context

ADR 0017からADR 0020により、大学入試を見据えた応用・発展教材について、独自作成、権利メタデータ、図解の一時停止、1パターン1ページの学習フロー、数学Iの全4領域への展開まで整備した。

一方、数学A・数学II・数学B・数学C・数学III・物理基礎・物理・化学基礎・化学では、基礎教材と単元末演習は存在するが、数学Iと同じ形式で「考え方・着眼点 → 例題 → ステップバイステップ練習 → 実践」を学ぶ応用・発展導線がない。

公開済み科目間で学習体験を揃えるには、まず全領域に最低1つの発展パターンを置き、後から領域ごとの頻出パターンを追加できる共通基盤を作る必要がある。

## Decision

### 1. 数学I以外の9科目・34領域へ発展パターンを配置する

次の34領域を初期カバレッジ対象とする。

- 数学A: 3領域
- 数学II: 5領域
- 数学B: 3領域
- 数学C: 3領域
- 数学III: 3領域
- 物理基礎: 5領域
- 物理: 4領域
- 化学基礎: 3領域
- 化学: 5領域

各領域に少なくとも1つの `advanced` パターンを置く。数学IはADR 0020で定めた各領域4パターン以上、`application` と `advanced` の両方を持つ基準を維持する。

この初期展開は「各領域に発展学習の入口が存在すること」を保証するベースラインであり、各領域の発展パターン数を1件で固定するものではない。

### 2. 教材構造を全科目で統一する

各パターンは引き続き次の順で構成する。

1. 考え方・着眼点
2. 例題
3. ステップバイステップの練習
4. 実践

数学では複数の定理・式・条件の接続、理科では複数法則の接続、限界条件、量的関係、観測結果の解釈などを発展パターンとして扱う。

単なる数値の巨大化や計算量の増加だけを「発展」としない。

### 3. 数学I向け表示コンポーネントを科目共通へ一般化する

`AdvancedPatternIndex.astro` と `AdvancedPatternPage.astro` は `MathCourseInfo` を受け取り、科目名、科目ホーム、領域URL、応用・発展URLを動的に組み立てる。

数学Iからの既存呼び出しでは `math1Course` を既定値として扱い、既存URLと表示を維持する。

数学I以外は次の共通静的ルートで生成する。

```text
/{course}/entrance/{topic}/
/{course}/entrance/{topic}/{pattern}/
```

### 4. 発展教材レジストリから領域ページの導線を自動生成する

数学I以外の教材は `*-advanced.json` に複数の `topicSets` を保持し、`advanced-topic-sets.ts` で科目横断のレジストリへまとめる。

`MathAreaIndex.astro` は科目キーと領域キーから対応する発展教材を探し、存在する場合に「応用・発展へ進む」を自動表示する。

この方式により、各科目の領域ルートへ同じ変更を繰り返さず、教材データと導線の不整合を減らす。

### 5. 著作権・権利管理方針はADR 0017を継続する

すべての公開パターンは次を満たす。

- `rights.origin: "original"`
- `rights.reviewStatus: "reviewed"`
- 有効な `rights.reviewedAt`
- 外部問題本文、解答、図表などを保持する禁止フィールドを含めない
- 特定の過去問・市販教材の問題文を転載、軽微改変、言い換えして作らない

問題は抽象化した技能、解法、難易度、学習目標から独立して作成する。

### 6. 図解の一時停止を継続する

ADR 0019に従い、今回追加する応用・発展教材にも `diagram` フィールドを持たせず、文章と数式だけで構成する。

### 7. CIで全科目カバレッジと生成HTMLを検証する

`verify-entrance-content.mjs` を複数 `topicSets` を含む文書へ対応させ、次を検証する。

- 公開済み10科目の必須領域がすべて存在する
- 数学I以外の各領域に `advanced` が1件以上存在する
- 数学IのADR 0020基準を維持する
- パターンIDが全ファイルで一意
- 学習構造、権利メタデータ、図解禁止を満たす

さらにビルド後に、数学I以外の34領域について次を検証する。

- 基礎領域ページに応用・発展導線がある
- 応用・発展一覧ページが生成される
- 各パターン個別ページが生成される
- 「考え方・着眼点」「例題」「ステップバイステップの練習」「実践」が出力される
- 図解停止中の要素が出力されない

### 8. 新しい依存関係は追加しない

既存のAstro、TypeScript、Biome、MathLive、ブラウザ標準APIだけを使う。package.jsonとlockfileは変更しない。

## Consequences

公開済みのすべての科目で、基礎教材から同じ形式の応用・発展教材へ進めるようになる。

科目固有の発展教材はJSONへ分離され、共通レジストリと共通ルートで表示されるため、今後パターンを増やすときの重複実装が減る。

一方、数学I以外は初期段階では各領域1パターンが中心であり、数学Iのような複数パターンの厚みはまだない。今後は閲覧性と品質を維持しながら、領域ごとの典型・頻出パターンを追加する。
