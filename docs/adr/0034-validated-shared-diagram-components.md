# ADR 0034: 型付き図データを共有する作図コンポーネントを導入する

- Status: Accepted
- Date: 2026-08-30

## Context

数学・物理・化学・生物の説明では、文章と数式だけでは位置関係、接続、向き、構造を把握しにくい場合がある。また、学習者が補助線、回路、模式図などを作図して回答できる仕組みも必要になった。

説明用と回答用で別々の描画方式を持つと、同じ図の表現がずれ、教材データ、検証、専用記号の実装が重複する。任意のSVG文字列やHTMLを教材データとして扱う方式は、正しさの検証が難しく、実行可能な内容を混入させる余地も増える。

ADR 0019 は応用・発展教材の図解を一時停止し、再導入前に図の位置関係や幾何情報を検証する仕組みを別ADRで定めることを要求している。本ADRではそのための共通基盤を定義する。ただし、`src/content/entrance/` の既存教材形式には今回図を追加せず、ADR 0019 のCI禁止も現時点では維持する。

## Decision

### 1. 説明用と回答用で同じ DiagramScene を使う

図は `DiagramScene` として型付きデータで定義する。説明表示、作図回答の初期図、模範図は同じデータ形式を使う。

図形要素のIDは図内だけで一意とする。他要素や制約から参照する要素は教材側でIDを指定し、回答エディタ内で参照されない要素には実行時IDを付与できる。

各要素は `movable`、`deletable`、`resizable`、`rotatable` を個別に持てる。省略時はすべて不許可とする。学習者が新規作成する要素は、標準では移動・削除を許可し、拡大縮小・回転を不許可とし、問題側のツール定義で上書きできる。

### 2. SVGを描画基盤とし、任意SVG・HTMLを受け付けない

基本図形は点、線分、直線、円、楕円、多角形、矢印、円弧、ラベル、座標軸、サンプリング済み関数グラフとする。

描画はSVG DOM要素として生成し、教材データから `innerHTML`、任意SVG文字列、任意HTMLを挿入しない。関数グラフの `expression` は表示用メタデータに限定し、クライアントで評価しない。描画には `samples` の計算済み座標を使用する。

この実装のための外部描画ライブラリは追加しない。

### 3. 共通図形と分野別の意味的記号を分離する

数学・理科で共有する基本図形をコア型とし、物理・回路・化学・生物の専用記号は `kind: "symbol"` の意味的要素として保持する。

専用記号は表示時に共通図形へ展開し、展開結果は教材データへ保存しない。初期セットは頻出する代表記号に限定し、後から追加できる構造とする。単純な記号はデータ変換として実装し、特殊な操作が必要になった記号だけ専用処理を追加する。

### 4. 描画コア、説明表示、回答編集を分ける

構成を次の責務に分ける。

- `DiagramCanvas`: SVG描画コア
- `DiagramView`: 説明用表示とズーム
- `DiagramEditor`: 回答用の編集、Undo/Redo、ズーム、パン、ツール制限、模範図重ね合わせ
- `DiagramExercise`: 作図だけで回答する問題の外枠

`WorkedExample` は例題全体と各手順に `DiagramScene` を受け取れるようにし、本文中の別位置では `DiagramView` を直接配置できるようにする。

### 5. 回答作図は構造化ツールだけにする

初期実装ではフリーハンドを提供しない。問題側が許可したツールだけを表示し、ツールは選択後も連続して使用できる。選択ツール、Esc、キャンセル操作で作図ツールを終了する。

スナップ、方眼、角度補助、水平・垂直補助などは問題単位で有効化する。スナップ候補や成立状態は画面に常時表示せず、参照関係として内部データに保持する。

PCではポインター・ホイール、タッチ端末では大きめの操作対象とポインターイベントを基本とする。ズームとパンを提供する。キーボードだけですべての作図を完結することは初期要件にしない。

### 6. 作図回答は自動採点・永続化しない

作図回答は数式入力や選択式と混在させず、独立した問題として扱う。回答状態はページ内のメモリだけに保持し、LocalStorage、学習履歴、バックエンドには保存しない。

「答えを見る」を押すと、学習者の図を残したまま固定色の模範図を重ねる。一度模範図を表示した後は回答図を編集不可にし、模範図の表示・非表示だけを切り替えられる。初期実装では作図内容を自動採点しない。

### 7. 基準座標とレスポンシブ表示を併用する

教材側は基準座標を明示する。説明図では図の可読サイズを優先し、小画面で必要な場合は横スクロールを許可する。回答エディタでは初期図を表示領域に応じて均一に再配置できるが、学習者が追加した要素はその座標を維持する。

ズームや画面幅の変化によって学習者要素と初期図の位置関係がずれる場合は許容する。初期図と学習者要素の参照関係はデータとして保持するが、再配置時に学習者要素を強制追従させない。

将来の段階表示・アニメーションを追加できるよう `states` を型に持たせるが、初期実装では実行しない。

### 8. 図データを自動検証する

図データについて次をエラーとして扱う。

- 不正な幅・高さ・座標
- 未対応の要素種別や専用記号
- 図内の重複ID
- 存在しないID参照
- 不正な編集権限
- 回路制約から回路以外の専用記号を参照するなどの分野不整合

平行、垂直、角度、距離、比率、包含、順序などについて、基準座標が指定制約を満たさない場合は警告する。制約が競合する場合は意味的な関係を優先し、完全一致を要求せず近似配置の対象とする。

JSON教材内の図データはCIで検証し、描画コンポーネントに渡されたデータもビルド時に検証する。構造・分野検証のエラーはビルドを失敗させる。

## Consequences

説明用と回答用で図データ、専用記号、検証ロジックを共有できる。任意SVGや実行可能な式を教材データから排除するため、公開リポジトリで扱う教材として入力面を限定できる。

一方、初期実装は自動採点、フリーハンド、完全な制約ソルバー、段階アニメーションを提供しない。専用記号も代表的なものから始めるため、教材追加に合わせて記号ライブラリと分野別検証を拡張する必要がある。

ADR 0019 の `src/content/entrance/` に対する図解禁止はこの変更では解除しない。入試・発展教材へ図を再導入するときは、当該教材形式から `DiagramScene` を参照・描画し、必要な分野制約が自動検証できることを確認してから、ADR 0019 の該当決定を置き換える。
