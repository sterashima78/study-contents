# ADR 0035: 説明図の任意色指定と数学座標計算ヘルパーを導入する

- Status: Accepted
- Date: 2026-08-30
- Related: ADR 0019, ADR 0034

## Context

ADR 0034 で、説明表示と作図回答に共通の `DiagramScene` を導入し、任意SVG・HTML・実行可能な式を教材データから排除した。

数学Iで説明図の利用箇所を検討すると、同じ座標上で複数の放物線を比較する場合や、補助線・注目部分を区別する場合など、教材作成者が要素ごとに色を指定できる必要がある。一方で、教材データから `style`、`stroke`、`fill` を任意指定できるようにすると、描画責務が教材へ漏れ、ADR 0034 の入力境界も広がる。

また、`functionPlot` は安全性のため計算済み `samples` を描画する設計だが、教材ごとにSVG座標を手計算すると、関数の係数・定義域と表示図が別々に管理され、式と図の不一致を再発させる可能性がある。数学座標から表示座標へ変換し、同一パラメータからサンプル点を生成する共通ヘルパーが必要である。

## Decision

### 1. 図形要素に `color` を追加する

`DiagramElementBase` に任意の `color?: string` を追加し、基本図形と分野別記号のどちらでも利用できるようにする。

教材作成者は `#2563eb`、`rgb(...)`、`hsl(...)`、`oklch(...)`、色名など、ブラウザがCSSの色として解釈できる文字列を指定できる。

### 2. 色は SVG の `color` と `currentColor` だけで適用する

教材データの `color` は要素を包むSVGグループの `color` 属性へ渡す。線、文字、点などの描画は既存どおり `currentColor` を利用する。

教材データから次を直接指定する仕組みは追加しない。

- 任意の `style`
- 任意の `stroke`
- 任意の `fill`
- CSS宣言列
- 任意SVGやHTML

これにより色の自由度は確保しつつ、教材が描画実装や実行可能な内容を直接注入する経路を増やさない。

### 3. 模範図の固定色を優先する

作図回答で模範図を重ねる場合は、教材側の `color` を適用せず、`DiagramCanvas` の model tone が持つ固定色を優先する。

説明図や通常表示では教材側の色を使えるが、回答図と模範図の視覚的な区別は維持する。

### 4. `color` の構造検証を行う

`validateDiagramScene` は `color` が指定された場合、空でない256文字以内の文字列であることを検証する。

CSS Color仕様すべてを独自パーサーで再実装しない。実際の色構文の解釈はブラウザに委ねる。無効な値は色として適用されないが、`style` や別のSVG属性へ展開しないため、任意宣言の注入には利用しない。

### 5. 数学座標とSVG座標の共通変換を追加する

`src/lib/diagram/math.ts` に、数学教材向けの計算ヘルパーを置く。

初期実装では次を提供する。

- `createCartesianTransform`: 数学座標とSVG座標の相互変換
- `createCartesianAxes`: 変換設定から座標軸要素を生成
- `sampleFunctionPlot`: 教材コード側の関数からサンプル点を生成
- `createQuadraticPlot`: 係数 `a`, `b`, `c` から二次関数のサンプル点と表示用式を生成

外部描画ライブラリは追加しない。

### 6. 実行可能な式を教材データへ戻さない

`sampleFunctionPlot` が受け取る関数はTypeScript教材コード側で実行され、生成結果だけが `FunctionPlotElement.samples` になる。

`FunctionPlotElement.expression` は引き続き表示用メタデータとし、ブラウザで評価しない。JSON教材から式文字列を読み取って `eval`、`Function`、動的インポート等で実行する仕組みは追加しない。

### 7. 計算不能な点を暗黙に補間しない

関数サンプリングで有限数ではない値が発生した場合はエラーにする。

不連続関数を扱う場合、1本のpolylineで不連続点をまたいで結ばず、教材側が区間を分けて複数の `functionPlot` として定義する。

### 8. 数学教材では手入力サンプルよりヘルパーを優先する

二次関数など、数式パラメータから機械的に計算できる説明図では `samples` の手入力を避け、計算ヘルパーを優先する。

問題文、表示式、グラフを生成する元パラメータを共有できる場合は共有し、式と図の不一致を減らす。

### 9. ADR 0019 の入試・発展教材に対する図解停止は維持する

本ADRは作図基盤の能力を拡張するが、`src/content/entrance/` への図解再導入を決定するものではない。

入試・発展教材の図解禁止を解除する場合は、対象教材のパラメータと図の生成・検証方法を確認したうえで、ADR 0019 の該当決定を別ADRで明示的に置き換える。

## Consequences

説明図では、比較対象や重要箇所を教材意図に合わせた色で区別できる。色指定は `color` だけに限定されるため、任意SVG・HTMLを禁止する既存の安全境界を維持できる。

関数グラフでは、数学座標からSVG座標への変換やサンプル点生成を教材ごとに手書きする必要が減る。特に数学Iの二次関数では、係数とグラフを同一入力から生成しやすくなり、図の数学的不整合を減らせる。

一方、ヘルパーは完全な数式パーサーやグラフ描画エンジンではない。不連続関数、複雑な目盛、特殊な座標系などは必要になった時点で用途を限定して拡張する。
