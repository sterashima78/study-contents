# ADR 0005: 利用ライブラリは確認時点の最新リリースへ固定する

- Status: Accepted
- Date: 2026-08-29
- Updated: 2026-09-03

## Context

このリポジトリでは、利用ライブラリを最新に保つ方針としている。

2026-09-03 の公開レジストリ確認時点で、Astro は `7.2.10`、MathLive は `0.110.0`、Biome は `2.5.11`、`@mlc-ai/web-llm` は `0.2.84` が利用可能である。pnpm は12系の最新公開版として `12.2.1` が利用可能である。

WebLLMについてはAndroid実機の原因分離のため0.2.82へ一時固定していたが、ADR 0094で互換性検証段階を終了し、最新版利用原則へ戻す。互換性調査のため旧版を一時採用する場合も、恒久的な例外にはせず、解除条件と検証結果をADRへ記録する。

存在しないバージョンや、公開レジストリの現行情報と一致しないバージョンを設定すると、CIやデプロイ時の依存関係インストールが失敗する。また、直接依存だけを固定しても推移的依存を毎回解決すると、同じコミットでもビルド時点によって依存グラフが変化する可能性がある。

## Decision

### 1. バージョン更新時は公開レジストリの現行情報を確認する

`package.json`、CI、デプロイ設定を更新する前に、npm など公式の公開レジストリで実在する最新版を確認する。

### 2. 依存関係は再現性のため完全なバージョンで固定する

教材サイトは静的サイトであり、ビルド結果の再現性を優先するため、主要な依存関係と開発ツールは完全なバージョンで指定する。

### 3. pnpm lockfileをリポジトリで追跡する

`pnpm-lock.yaml` をコミットし、直接依存だけでなく推移的依存を含む解決結果を固定する。依存更新時は `package.json` とlockfileを同じ変更で更新し、CIでインストールとビルドを確認する。

公開リポジトリであることを踏まえ、lockfileによってレビュー対象となる依存グラフを明示し、意図しない推移的依存の変化を減らす。

### 4. pnpm は12系の最新公開版を使う

2026-09-03 の確認時点では `pnpm@12.2.1` を `packageManager`、CI、デプロイの3か所で一致させる。

今後12系の更新版が公開された場合は、互換性とCIを確認したうえで12系の最新公開版へ更新する。

### 5. バージョンの食い違いを作らない

パッケージマネージャのバージョンはローカル利用を示す `packageManager` と GitHub Actions のセットアップ指定で同一にする。Biomeのバージョンを更新した場合は `biome.json` の `$schema` も同じバージョンへ同期する。WebLLMのバージョンを更新した場合は `STUDY_AI_RUNTIME_VERSION` とStudy AI境界検証も同じバージョンへ同期する。

### 6. 互換性調査による旧版固定は期限付きの例外としてADR管理する

最新版で実機回帰が疑われる場合は、原因分離のため旧版を完全固定して比較してよい。ただし、対象条件、解除条件、検証結果をADRへ記録し、検証完了後は最新版へ戻すか、旧版継続の新しい根拠を明示する。

## Consequences

CIで実在しないツールバージョンを取得しようとする失敗を避けられる。完全固定とlockfileにより更新は自動ではないため、ライブラリ更新時には公開レジストリの最新版確認、lockfile更新、設定・診断表示の同期、CI実行をセットで行う。
